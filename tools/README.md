# Tools

Scripts for the mechanical work. All are PowerShell 5.1 and are run from the repository root.

| Script | Purpose | Example |
|---|---|---|
| `check.ps1` | Builds the app and prints one verdict line; lists compiler errors on failure; `-Task <name>` runs another Gradle task. Full output in `build\logs\check.log`. Fails at once if an interrupted `mutate.ps1` run left a backup | `.\tools\check.ps1 -Quiet` |
| `check.ps1 -Test` | Same verdict line, but runs the unit tests (`testDebugUnitTest`); failing tests are listed from the Gradle output | `.\tools\check.ps1 -Test -Quiet` |
| `check.ps1 -Tests` | Runs only the named test classes (Gradle `--tests` filters); implies `-Test` | `.\tools\check.ps1 -Quiet -Tests 'com.donuts.game.GameInputTest'` |
| `coverage.ps1` | Runs the unit tests with JaCoCo (switched on by the init script `coverage.gradle`, so `app\build.gradle` is unchanged) and prints line and branch coverage per file; `-Lines` also writes the uncovered line numbers to `build\logs\coverage-lines.txt` | `.\tools\coverage.ps1 -Quiet -Lines` |
| `mutate.ps1` | Mutation check: changes one operator at a time in a source file, runs the tests and lists the changes no test caught; the file is always restored; `-WhatIf` lists the mutants only and restores a file an interrupted run left mutated (it refuses if the file was edited since); `-From`/`-To` limit it to a doc-map line range, `-Max` caps the mutants (30) | `.\tools\mutate.ps1 -File GameBoard.kt -From 141 -To 156 -Tests 'com.donuts.game.GameBoardTest'` |
| `env.ps1` | Dot-sourced by the build scripts, `emu.ps1` and `release.ps1`: sets `JAVA_HOME` (Android Studio's JDK), in a git worktree with no `local.properties` `ANDROID_HOME` from the main checkout, and `$envSdk` to the SDK folder | `. .\tools\env.ps1` |
| `code-map.ps1` | Lists source files with line counts, one file's functions with line numbers, or finds a function by regex; `-Doc` prints a Markdown doc map, `-UpdateDoc <file>` refreshes its doc-map markers | `.\tools\code-map.ps1 -Match "sticker"`; `.\tools\code-map.ps1 -UpdateDoc .\CLAUDE.md` |
| `emu.ps1` | Drives the emulator: `Start` an AVD, `Install` the debug build, take a `Shot` into `build\shots`, `Tap` a point, `Drag` a finger path, `Plant` a saved board (to set up a power-up), `Stop` the emulator and the adb server; `Start` gives the emulator 4 GB of RAM unless `-Memory` says otherwise (the 2 GB AVD config lets the low-memory killer close the app) | `.\tools\emu.ps1 Shot -Name board` |
| `gallery.ps1` | Renders every screen state to PNGs on the JVM (Robolectric, test class `ScreenGallery`, switched on by the init script `gallery.gradle`) at phone, landscape, small, tablet and tablet-portrait sizes, into `build\shots\gallery`; no window insets, so use `emu.ps1` for those | `.\tools\gallery.ps1 -Quiet`; `.\tools\gallery.ps1 -Size tablet` |
| `shot-diff.ps1` | Compares two folders of PNGs pixel by pixel (size and every ARGB value) and lists the shots that differ with the changed-pixel count and bounding box, or that are in one folder only; exits 1 on any difference; reads only. Use it with two `gallery.ps1 -Out` runs around a refactor. The parent gate's question is random, so `25-settings-gate` shots differ between runs | `.\tools\shot-diff.ps1 -Before build\shots\before -After build\shots\after -Quiet` |
| `bump-version.ps1` | Sets `versionName` and raises `versionCode` in `app\build.gradle` for the next Play upload; `-Code` sets the code explicitly; `-WhatIf` shows the change only | `.\tools\bump-version.ps1 -Name 2.0.5` |
| `..\release.ps1` | Builds the signed release bundle (see the README's release checklist) | `.\release.ps1` |
| `balance.ps1` | Runs the balance simulation (test class `BalanceSim`, switched on by the init script `balance.gradle`): 7 player models (incl. kidLearner56 and kidLearner78) x grid 6 and 8 x 25 seeds x 150 moves, plus the 6x6 kidLearner variants `types6` (the old six-type 6x6), `golden08` and `drought`; base plays five types on 6x6 as the game does, into `build\balance` (`scenarios.csv`, `moves.csv` (both with a `variant` column), `summary.md`, `invariants.txt`) | `.\tools\balance.ps1 -Quiet` |
| `colorblind.ps1` | Colour-blind check: simulates protanopia, deuteranopia, tritanopia (Machado 2009) and greyscale over the gallery PNGs into `build\shots\colorblind` (one PNG per mode plus a `__sheet.png` per shot) and prints the closest donut colour pairs from `DonutType.kt` per mode (CIE76 Delta E); `-FailOnCollision` exits 1 on a pair under `-Threshold`, `-PaletteOnly` skips the images | `.\tools\colorblind.ps1 -Quiet` |
| `families-check.ps1` | Play Families release check: builds the release merged manifest and the `releaseRuntimeClasspath` report (or takes `-Manifest`/`-Dependencies`) and fails on any permission past vibrate (AD_ID, network, location and purchases named), a debuggable build, an ad, analytics, tracking or purchase SDK in the manifest or among the libraries, or an unreviewed library; changes nothing; `release.ps1` runs it before building | `.\tools\families-check.ps1 -Quiet` |
| `test-env.ps1` | Tests `env.ps1` on scratch checkouts in the temp folder (no Gradle, no SDK): escaped `sdk.dir`, `ANDROID_HOME` winning, no SDK, a worktree taking the main checkout's SDK, `JAVA_HOME` kept | `.\tools\test-env.ps1` |
| `test-families-check.ps1` | Tests `families-check.ps1` on fixture manifests and dependency reports in `build\test-families-check` (no Gradle): a clean release passes; AD_ID, network, location, unknown permissions, debuggable, ad SDKs in the manifest or libraries, unreviewed libraries, an empty report and missing or broken files fail | `.\tools\test-families-check.ps1` |
| `test-colorblind.ps1` | Tests `colorblind.ps1` on a scratch PNG in `build\test-colorblind`: every mode is written, greyscale is grey, protanopia brings red and green together, `-WhatIf` writes nothing, a missing folder fails | `.\tools\test-colorblind.ps1` |
